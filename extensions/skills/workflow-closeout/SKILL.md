# Close out the current task

Find the existing task authority and project document mapping before editing. Use the installed delivery `docs/development/CLOSEOUT.md` when available. If no task authority exists, report the result and remaining work without inventing a second task database.

Compare the requested scope with the diff and available verification evidence. Distinguish implementation, automated checks, human acceptance, deployment and external platform publication. Preserve unknowns, manual acceptance, submissions and external permissions as explicit remaining items. Do not turn code completion into end-to-end completion or reuse historical authorization.

Update only facts affected by this task, in their existing authoritative locations. Update a summary, rule or Runbook only when a stable fact changed and current evidence supports it. Contradictory documents need evidence-based reconciliation or an explicit unresolved note; newer prose alone does not prove production state.

Keep the task entry concise with outcome, evidence links, remaining work, blockers and next owner/action when known. Move lengthy history only to an existing archive convention, preserving references and user customizations; absent one, propose archival rather than inventing another authoritative file. Do not archive pending acceptance or silently remove previous evidence.

Preserve unrelated and uncommitted user edits. Follow the user's scope for local edits; do not infer permission to commit, push, release, deploy or change policy. Return changed documents, verification evidence, incomplete stages and next actions. If the user requested only a review, report proposed updates without editing.
