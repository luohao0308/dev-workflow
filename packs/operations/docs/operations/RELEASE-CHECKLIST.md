# 发布检查清单

## 1. 变更与授权

- [ ] 目标环境、范围、版本身份和发布窗口明确。
- [ ] 任务、设计、计划、契约和迁移状态允许发布。
- [ ] 本次操作已有独立授权，记录 repo/环境、operation、不可变版本/产物、目标、actor、expiry；未从 push、PR 或 merge 权限推导。
- [ ] PR、required CI、独立 Review、CODEOWNERS 和 environment approval 等适用门禁已通过；实现者不是唯一审批者，AI review 不计作独立批准。
- [ ] 工作树/分支干净，发布提交已通过项目质量门禁。

## 2. Preflight

- [ ] 重新获取当前运行版本、配置来源、依赖健康和容量。
- [ ] 核对目标提交/产物、部署配置和运行拓扑。
- [ ] 数据迁移前备份成功且恢复入口可用。
- [ ] 回滚版本、回滚命令和停止条件已确认。
- [ ] migration/backfill、traffic switch、rollback 和凭据操作分别具备目标明确的授权；缺失或无法验证时停止。
- [ ] 不依赖历史文档中的动态值直接操作。

## 3. 构建与部署

- [ ] 从可追溯、干净的源构建不可变产物。
- [ ] 记录 commit/tag/digest 等产物身份。
- [ ] 先在候选/测试入口验证，再切换正式流量（如适用）。
- [ ] 迁移顺序遵守兼容设计，不提前删除旧字段或能力。

## 4. 发布后验证

- [ ] 进程/容器/实例存活且健康检查语义正确。
- [ ] 关键依赖、数据库迁移和队列/任务状态正常。
- [ ] 至少完成一个核心业务冒烟和一个鉴权/错误冒烟。
- [ ] 日志、指标、追踪和告警无异常增量。
- [ ] 外部入口、缓存、代理或网关行为已验证（如适用）。

## 5. 失败与回滚

- [ ] 达到停止条件时停止继续扩大变更。
- [ ] 使用已验证的上一个产物/配置回滚，或按设计执行前滚修复。
- [ ] 回滚后重新执行健康、业务和观测验证。
- [ ] 数据不可直接回滚时，按恢复 Runbook 处理并保留审计证据。

- 迁移/备份身份：
- 验证结果与证据：
- 回滚点：
- 剩余风险/后续任务：
